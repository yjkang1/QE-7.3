7. WHAT V4 IS
   S3/V3 moved both branches onto stock ldaU, at the price of ONE Hubbard
   channel per atomic type: ehub_l(m,nt) was collapsed to Hubbard_l(nt)+1 and
   multi-channel types were refused.  V4 removes that restriction.

   The key finding: ldaU ALREADY holds the manifold in the shape the kernels
   want.  init_hubbard (PW/src/ldaU.f90:290-320) builds ll(m,nt), which labels
   the concatenated manifold in the SAME order ldaV uses (Hubbard_l, then
   Hubbard_l2, then Hubbard_l3).  Map:
        ehub_lm(nt)    <-> ldim_u(nt)          -> lm(nt)
        ehub_lm_max    <-> ldmx_tot            -> lm_max
        ehub_l(m,nt)   <-> ll(m,nt) + 1        -> lch(m,nt)
        ofstv(na)+m    <-> three-way           -> ofs(m,na)
   Only the last is genuinely missing, because ldaU stores the PROJECTORS in
   up to three blocks (offsetU / offsetU_back / offsetU_back1) rather than
   contiguously.  New MODULE hp_acbn0_man builds it, following
   force_hub.f90:1060-1071 and copy_U_wfc (ldaU.f90:604-620):
        m <=   2*l+1       -> offsetU(na)       + m
        m <= 2*(l+l2+1)    -> offsetU_back(na)  + m -   (2*l+1)
        otherwise, backall -> offsetU_back1(na) + m - 2*(l+l2+1)

   XML round-trip checked with the SAME criterion that found bugs 1-3:
   Hubbard_l2/l3/U2/backall are passed at pw_restart_new.f90:1322 and read at
   qexsd_copy.f90:434-441, and init_hubbard re-runs on hp.x's read path.  A
   background channel is ACTIVE only when Hubbard_U2 /= 0 (ldaU.f90:249), so
   the HUBBARD card must give it a nonzero value; 0.0001 eV is enough.

8. HOW THE 225 m-INDICES WERE RESTORED (scratchpad/restore_m.py)
   Undoing the collapse means putting the right m back at 261 sites.  Used the
   fork as an ORACLE rather than doing it by hand: align our routine with
   new_ns_v.f90 statement by statement; wherever an aligned fork line carries
   ehub_l(mX,nt) and ours carries lch(nt), splice the index back -- but ONLY
   when the type argument matches AND the occurrence counts agree.
      215 sites resolved automatically
       10 flagged  -> exactly the sites where an intended edit had broken the
                      alignment; done by hand against the fork.

   BUG CAUGHT BY THAT CHECK.  One of the ten was
        fork:  IF ( ehub_l(m1,nt) == 1 .AND. ehub_l(m2,nt) == 1 ) THEN
        V3:    IF ( lch(nt) == 1 ) THEN
   V3's simplification is a tautology for one channel and WRONG once m1 and m2
   can sit in different channels.  A first version of the script silently
   skipped it: the guard meant to protect assignments (lch\(nt\)\s*=) also
   matched the comparison (lch(nt) ==).  Fixed with a negative lookahead.
   Same class of trap as everything else in this project.

9. SELF-INFLICTED BUG, CAUGHT BY ITS OWN GUARD
   hp_acbn0_build_man ends by asserting every manifold state landed on a real
   wfcU column (1 <= ofs(m,na) <= nwfcU).  First run: fired on EVERY case.
   Cause: the blanket rewrite of offsetU(X)+Y -> ofs(Y,X) had also rewritten
   the module's OWN definition of the map, into
        ofs(m,na) = ofs(m,na)
   so ofs stayed 0 for every main channel.  Without the assertion this would
   not have crashed - every projection would have silently read wfcU column 0.
   Exactly the failure mode of bugs 3 and 4, which is why the guard exists.
   (Note: the diagnostic WRITEs were lost to Fortran output buffering when
   MPI_Abort fired; putting the numbers into the errore message string is the
   reliable way to get them out.)
